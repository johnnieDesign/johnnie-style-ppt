# 장표 디자인 스킬 추천

장표의 겉모습은 세 곳에서 정해진다: `index.html` 의 **서체**(@font-face) · **테마**(:root), `scenes/STYLE.md` 의 **디자인 방향**.
디자인 스킬은 이 세 곳과 **견본 3장면**을 만드는 데 쓴다. 엔진(무대 1920×1080 · 마커 · 멈춤 계산 · 진행 바 · 발표자 화면)은 바꾸지 않는다.

**디자인 스킬은 모두 선택이다.** 하나도 없어도 기본 안(johnnie 스타일 기본값)으로 장표를 만든다.
쓰는 사람마다 설치된 스킬이 다르니, 있는지 먼저 보고, 없는 스킬은 설치를 **제안만** 한다. 사용자가 고르지 않으면 받지도 설치하지도 않는다.

## 흐름

1. **있는지 보기**

   ```bash
   python3 <이 스킬 폴더>/scripts/design_skills.py
   ```

   스킬마다 `있음`(설치됨) · `있음(연결 안 됨)`(이 기기 스킬 모음에는 있다) · `받아 둠`(전에 이번만 쓰기로 받음) · `없음`(출처 · 라이선스 · 부작용)이 나온다.
2. **상황 파악**: 발표까지 남은 시간 · 디자인 초안(Figma)이나 레퍼런스(사이트 · 이미지)가 있는지 · 청중(사내 / 대외) · 새로 만들기인지 다듬기인지. 모르는 것만 묻는다
3. **추천 1~3안 + 기본 안**: 아래 표에서 고른다. 안마다 주 스킬 최대 1개 + 보조, **이유**(이 발표의 어떤 점 때문에), **예상 시간**, **부작용**, 그리고 **설치 상태**. 마지막은 늘 **기본 안**(설치 없음 · 추가 시간 없음)
   - 설치되지 않은 스킬이 든 안은 설명에 "선택하면 이번 발표에만 받아서 씁니다(설치하지 않음) · 출처 · 라이선스"를 붙인다
4. **승인**: AskUserQuestion 이 있으면 안마다 옵션 하나(label = 안 이름, description = 이유 · 시간 · 부작용 · 설치 상태), 없으면 번호 목록. 승인 전에는 어느 스킬도 읽거나 받지 않는다
5. **실행**: 고른 스킬의 SKILL.md 를 읽고 그대로 따른다(디자인 스킬은 Skill 도구로 못 부르는 경우가 많다. 경로로 읽는다)
   - `있음` · `있음(연결 안 됨)` · `받아 둠`: 표시된 경로의 SKILL.md
   - `없음`: `python3 <이 스킬 폴더>/scripts/design_skills.py fetch <이름>` → 캐시에 받은 SKILL.md(설치는 안 한다). 스크립트 · 참고 문서의 기준 폴더는 그 스킬 폴더다
6. **끝난 뒤**: 이번에만 받아 쓴 스킬이 쓸 만했으면 "계속 쓰려면 설치할까요?"를 한 번 묻는다. 승인하면 `design_skills.py install <이름>`(Codex 는 `--dest ~/.codex/skills`). 묻는 것은 한 번만
7. **기록**: design-skill-manager 가 있으면 그 흐름(추천 → 승인 → 실행 → `time-log.md` 기록)과 조합 규칙을 따른다. 없으면 걸린 시간만 보고한다

## 디자인 스킬에 넘길 맥락

디자인 스킬은 보통 웹페이지를 만든다고 가정한다. 시작할 때 아래를 그대로 넘긴다.

- 결과물: `index.html` 의 서체 블록 · `:root` 토큰, `scenes/STYLE.md` 의 디자인 방향, 견본 3장면(`scenes/NN.js`). 엔진 JS 는 고치지 않는다
- 무대: 1920×1080 고정, 멀리서 본다. 내용은 y 150~960, 좌우 여백 100. 화면 글자 22px 이상
- 장면마다 굵게 갈 곳은 하나. 강조는 가운데 정렬, 자료 · 설명은 왼쪽 정렬
- 실제 서비스(티켓 · 시트 · 문서 · 슬랙)는 밝은 창(`.app`)으로 다시 그리고 그 로고를 쓴다
- 모션은 엔진 페이드(`fx-fade` · `fx-pop` · `fx-wipe` · `fx-draw`)만. 장면마다 다른 모션을 만들지 않는다
- **서체는 이 기기에 설치된 것을 `local()` 로 쓴다.** 웹 서체 CDN 을 붙이지 않는다. 공유본은 `build_single.py` 가 그 서체 파일을 찾아 넣고, 못 찾으면 공유본을 만들지 않는다. 서체를 바꾸면 `python3 tools/build_single.py --list-fonts <검색어>` 로 설치된 이름을 확인해 local() 에 적는다

## 견본 3장면

디자인 단계의 끝은 견본 3장면이다. 성격이 다른 셋을 고른다: **강조 한 문장 · 숫자나 대비 · 서비스 창이 나오는 자료 장면.**
`shoot.mjs` 로 찍어 사용자에게 보여 주고 확인받은 뒤 나머지 파트로 넘어간다. 확인받은 셋의 문단 번호와 쓴 스킬(또는 기본 안)을 STYLE.md 디자인 방향에 적는다.
