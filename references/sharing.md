# 발표 준비 · 공유

## 발표 기기로 옮기기

- 로컬 경로는 기기를 넘지 않는다. **발표 폴더를 통째로 zip** 해서 옮기고(메신저 나에게 보내기 · 클라우드 드라이브) 발표 맥에서 푼다. `audio/paras/` 캐시까지 가면 그 기기에서도 고친 문단만 음성을 다시 만든다
- 옮긴 뒤엔 그 기기 사본이 최신이다. 프로젝트 노트에 "최신 사본: <기기> <경로>" 한 줄

## 발표 기기 점검 (발표 전날까지)

1. **서체**: Chrome 으로 장표를 열고 시작 화면 서체 확인 문구를 본다(`shoot.mjs` 도 첫 줄에 `서체: …` 로 알려 준다. 아무것도 받지 않는다). 못 찾으면 `python3 tools/build_single.py --list-fonts <검색어>` 로 그 기기의 서체 이름을 찾아 `index.html` 서체 블록 `local()` 에 더한다
2. **여는 방법**: `python3 -m http.server 8765 --bind 127.0.0.1 -d deck` → `http://127.0.0.1:8765/#presenter`. 서버를 띄운 터미널은 발표 끝까지 켜 둔다(파일로 연 발표 화면이 안 보인 적이 있다)
3. **디스플레이는 확장**: 미러링이면 발표자 대본이 청중에게 보인다
4. `발표 화면 열기` → 새 창을 프로젝터로 → `F`. 발표자 화면 위쪽에 `● 발표 화면 연결됨`
5. **클리커**: → · PgDn 으로 넘어가는지
6. **통 리허설 1회**: 장표만 보기로 끝까지. 누름이 바쁜 곳은 구절을 떨어뜨리거나 합친다
7. 노트북 크기에서 발표자 대본이 넘치지 않는지: `node tools/shoot.mjs --presenter 1470x956 --port 9371 --out <임시 폴더>/pv`

## 공유: 한 파일 (서체 포함이 스펙)

옆 파일을 못 읽는 곳(HTML 을 띄워 주는 공유 서비스 · 클라우드 드라이브 · 메일 · Artifact 한 페이지)에는 한 파일로 올린다.
**공유본에는 장표 서체가 반드시 들어간다.** 보는 사람 기기에 서체가 없어도 발표 때와 같은 모양이어야 하기 때문이다.

```bash
python3 tools/build_single.py --mode rehearse            # 보는 사람은 '프레젠테이션'(음성 자동 재생)으로
python3 tools/build_single.py --mode rehearse --kbps 64  # 크기 제한을 넘으면
node tools/check_single.mjs "dist/<제목>.html" <임시 폴더>/single
```

- `build_single.py` 는 `index.html` 서체 블록의 `local()` 이름으로 이 기기에 설치된 서체 파일을 찾아, 장표에 쓴 글자만 남긴 woff2 로 넣는다(한국어 서체 한 굵기 50~60KB). 이미지는 WebP 로 줄인다
- 서체 도구(fontTools · brotli · Pillow)가 없으면 처음 한 번 `~/Library/Caches/johnnie-style-ppt/venv` 에 받아 그걸로 다시 실행한다(인터넷 필요, 1분 안팎). 처음이면 사용자에게 한 줄 알린다. 받지 못하면 공유본을 만들지 않는다
- **서체를 하나라도 못 찾으면 공유본을 만들지 않는다.** 서체를 설치하거나(파일 더블클릭 → 설치), `--list-fonts <검색어>` 로 이 기기에 설치된 이름을 찾아 `local()` 에 더한다. 같은 서체도 기기마다 이름이 다를 수 있다
- `check_single.mjs` 는 공유 서비스처럼 샌드박스 iframe(출처 없음 · localStorage 막힘)에 띄워 서체 로드 수 · 이미지 깨짐 · 음성 길이 · 콘솔을 보고, 처음부터 끝까지 눌러 찍는다. 마지막에 **서체 내장 검사**(설치 서체를 못 쓰게 바꾼 사본으로 다시 열기)를 한다. `서체 내장(설치 서체 없이): N/N 로드 → 통과` 가 아니면 종료 코드 1 이고, 공유하지 않는다
- 서비스 창(`.app`)의 UI 글자는 맥에서는 시스템 서체, 그 밖의 기기에서는 넣은 보조 서체로 보인다
- 크기: Artifact 한 페이지는 16MB 까지. 공유 서비스마다 제한이 다르다(10MB 인 곳이 있었다). 넘으면 `--kbps 64` 로 음성부터 줄인다

### HTML 을 띄워 주는 공유 서비스

- 올린 HTML 한 파일을 샌드박스 iframe 에 띄우는 곳이 많다. 옆 파일을 못 읽고, localStorage 는 읽기만 해도 예외가 날 수 있다. 엔진은 이 조건에서 돌도록 만들어져 있다. 올리기 전에 `check_single.mjs` 로 본다
- **권한은 파일을 둔 곳(클라우드 드라이브)의 공유 설정을 그대로 따른다.** 조직 설정으로 "링크가 있는 모든 사용자" 공유가 막혀 있으면 공유 대상을 직접 넣는다(그룹이나 받을 사람 메일을 뷰어로, 댓글을 받으려면 댓글 작성자로, 이메일 알림은 끈다)
- 고친 뒤 다시 올릴 땐 드라이브의 **새 버전 업로드**를 쓴다(링크가 그대로다)
- 공유본은 보는 용도다. 발표는 로컬로 한다

## 공유: Artifact

- `build_single.py` 결과를 한 페이지로 게시한다(16MB 이하). 서체 · 이미지 · 음성이 모두 data URI 라 Artifact CSP 에 안 걸린다. 음성 재생은 첫 게시 때 열어서 확인한다
- 여러 파일로 따로 올리지 않는다. Artifact 는 `.m4a` 를 서빙하지 않고 서체 파일도 막아서 서체가 빠지기 쉽다
- Artifact 안에서는 `발표 화면 열기`(새 창)가 막힐 수 있다. Artifact 는 공유 · 다른 기기 확인용, 발표는 로컬로
- 게시는 비공개로 시작한다. 다른 사람이 보려면 사용자가 Share 에서 공유한다
